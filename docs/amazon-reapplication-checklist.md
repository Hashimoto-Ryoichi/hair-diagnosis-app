## 過去2回の却下原因（同じ轍を踏まないための記録）

| 日付 | 却下理由（メール文言） | 実際の原因 |

### 2026-07-26に追加で発見・修正した潜在原因

商品ボタンが `rel="noopener noreferrer"` だった。**`noreferrer` はリンク先に「どのサイトから来たか」を一切送らない**ため、却下文言「トラフィックのソースを特定できませんでした」を技術的に再現しうる状態だった。規約 参加要件6(v)（お客様がクリックスルーしたサイトをAmazonが判断できないようURLをクローク・ハイドしてはならない）にも抵触しうる。

→ アフィリエイトリンクの `rel` は **`nofollow sponsored noopener`** に統一。セキュリティ上必要なのは `noopener` だけで、`noreferrer` は付ける理由がない。チェック⑫で恒久ブロック。

さらに同日、次の2点も修正：

- **静的商品一覧を `<details open>` に**：折りたたみのままだとHTMLには存在してもブラウザで見た審査員がリンクに気づけない。却下理由が「リンクが確認できない」である以上、審査中は開いておく（チェック⑬）。**審査通過後は `open` を外して折りたたみに戻してよい。その際チェック⑬も削除する。**
- **sitemap.xml の `lastmod` を更新**：`2026-05-21` のまま（66日前）だった。審査基準は「コンテンツは60日以内に更新されていること」なので、実態は毎週更新しているのに期限切れを自己申告している状態だった。`changefreq` も monthly → weekly に修正。

  → **2026-07-30に自動化した。** 上の「今後は更新すること」という申し合わせを、同日にAIが実際に忘れた（ISSHI追加をデプロイしたのに lastmod は前日のまま）ため、人の記憶に頼るのをやめて機械で止めることにした。`.githooks/sync-sitemap.sh` を pre-commit から呼び、**index.html がステージされたコミットに限り** lastmod を今日の日付に書き換えて同じコミットに含める。ドキュメントだけの変更では発火しない（更新実態と申告をズラさないため）。同日2回目以降は何もしない。**このフックがあるので、以後 lastmod を手で直す必要はない。**

## 再申請の手順（この順番を厳守。審査は一発勝負＝却下された申請の再審査は不可）

1. **申請前の状態確認**
   - [ ] 本番 https://hair-diagnosis-app.vercel.app のソース表示（Cmd+Option+U）で `tag=` 付き静的リンクが見えること
   - [ ] サイトが60日以内に更新されていること（コンテンツ鮮度の審査基準）
2. **新規申請**（却下メール内の「別途申請」リンクから）
   - [ ] 登録サイト一覧に、Amazonリンクを置く場所を**全部**入れる（vercel.appのURL。note等に貼るならそのURLも）
   - [ ] Amazonリンクは登録サイト以外に貼らない（LINEトーク・メール・PDFへの直貼りは規約違反）
3. **新トラッキングIDの反映**（申請直後・審査が始まる前に）
   - [ ] 管理画面で新IDを**現物確認**（推測・記憶での入力は禁止）
   - [ ] `sh scripts/rotate-assoc-id.sh 新ID` を実行
   - [ ] コミット→デプロイ→本番ソース表示で `tag=新ID` を目視確認
4. **審査期間中（サインアップから180日以内に適格販売3件が必要）**
   - [ ] 自分での購入は適格販売にカウントされない
   - [ ] サイトの商品リストは最新に保つ（審査ヘルプに明記）
   - [ ] 「特別な計らい・報酬・インセンティブでリンク利用を促す」行為をしない（規約お役立ちリマインダー）
